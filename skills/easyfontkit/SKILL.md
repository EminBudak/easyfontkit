# easyfontkit

A CSS font stack says what a site asks for, not what the visitor sees, and a font's name says nothing about whether it is free. easyfontkit opens the site in a headless browser, asks Chrome which font it really drew each kind of text with, keeps the font files the page loaded, and reads each file's own license fields.

## Get the kit

```bash
node <skill>/scripts/easyfontkit.js <url> --out fonts/<name>
```

`<skill>` is this skill's folder. The script needs Node 22 or newer and Chrome, Chromium, Edge or Brave on the machine; it installs nothing and needs no API key. A run takes 15 to 60 seconds. A page whose fonts never come holds the run about 40 seconds longer: the load is waited for up to 30 seconds, and the page's fonts up to 5 seconds more before the scroll and again after it. Any page of a site works, and fonts can differ between a home page and its docs, so read the page whose look you need.

The folder has to be new, empty or hold an earlier kit. A new run into it replaces the earlier kit once the new one is whole. A run that fails or is stopped leaves the folder as it was: a kit an earlier run left there is still whole, and nothing is added.

## Use it

1. Read `fonts/<name>/FONTS.md` first. Its table gives each role's font, the weights the site uses, the license and the closest free font.
2. Each family's section says who made it, where it was served from and what its file says about its license. Open means it may be used under that license anywhere. Commercial means its maker sells it, and the site's license covers the site, not other work. Unknown means neither the file nor its source says, or the file did not load while the page was read, or easyfontkit did not read it. A system font is the visitor's own and comes with no file.
3. In CSS, import `fonts.css` from the kit folder and use `var(--font-heading)`, `var(--font-body)`, `var(--font-button)` and `var(--font-code)` for the site's own fonts, or the `-free` variables for the closest free ones. The font files are in `files/`.
4. Before a commercial or unknown font goes into work the user will publish, tell them which one it is and who sells it, and ask whether they hold a license. Until they answer, build with the `-free` variable. Open fonts need no question.
5. For images and video, name the families in prompts and titles, and hand the files in `files/` to tools that take a font file.
6. `fonts.json` holds the same facts for scripts.

## When it goes wrong

- A free match chosen by proportions has a similar x-height, cap height and width, which keeps line lengths and spacing close. It can still look different. Tell the user it is the nearest free font, not the same design.
- If a role shows a system font where you expected the brand's own, the site may load its fonts late. Try `--timeout 240`, which helps when the machine or the site was slow, and tell the user what you got. A web font whose file did not come while the page was read shows with an unknown license and a note, not as a system font.
- If the site answers with a bot check, the run stops and says so. Ask the user for the font names.
- If the page answers with an error status, the run stops, writes nothing and names the status and the address it ended on. After a 404, check the address with the user or read the site's home page. After a 401 or a 403, the page may need a login, or the site may turn away headless browsers. After a 500, a 503 or a 429, the site may be down or busy: try again later.
- If the address cannot be opened at all, redirects in a loop or its server does not answer, the run stops, writes nothing and says "Could not open <url>: <reason>". If a redirect, a script or a meta refresh sends the browser on to an address that cannot be opened, or a redirect sends it to a server that does not answer, it names that address instead. If the page moves itself on to about:blank, an empty page, the run stops and writes nothing too. Check the page in a normal browser.
- If the page stays blank because a style sheet it waits for never comes, the run stops, writes nothing and names that style sheet. Try again later, or check the page in a normal browser.
- If the machine is busy, the browser can be too slow to start or to open its page, or stop answering. The run stops, writes nothing and says so: "<browser> did not start in <n> s", "did not open a page in <n> s", "stopped answering" or "did not answer before the run's time ran out". Try again, and if it happens again, run with a longer `--timeout`, like `--timeout 240`. If it says "The run's time ran out before the text of <url> could be read", the page or the machine took the run's time before any text was read, and a note that says the time ran out before some roles could be read names the ones the kit lacks: run it again with `--timeout 240`.
- If the system cannot start the browser, the run stops and writes nothing. The message starts "No Chrome, Chromium, Edge or Brave found" or "<browser> did not start" and names the path CHROME_PATH or the search gave. Then it says what is wrong with that path, such as a folder or a file that may not be run, or the system's own reason it could not start the file, or, for a browser that ended before it answered, a line it printed, in quotes, and how it ended. That line is in the words of the program that printed it and often names what is wrong, such as a library the machine lacks, a program a script could not start or a chromium snap that is not installed: tell the user what it says. A sentence after it can say that the file is a program for another kind of machine, such as 64-bit ARM, macOS or Windows, and then the line is what /bin/sh made of it. Ask the user to fix that, to install Chrome or to point CHROME_PATH at the program of a browser that runs, and never guess a path.
- If it says the process, the browser or the system is short of open files, processes or memory, another browser does not help: do what the message says, raise the limit on open files as `ulimit -n` does, or run it again once fewer files or processes are open or more memory is free. The browser's own words for it may be the line in quotes, or another line it printed, such as "Too many open files" or "pthread_create: Resource temporarily unavailable". When the message also says that this process may have no more than a few hundred files open, or that this user runs nearly as many processes and threads as they may, that comes first, whatever the line in quotes says.
- If it says the browser's sandbox could not start here, another try does not help, and the line in quotes says which way it could not. "setuid sandbox: failed to move to new namespaces" or "Failed to move to new namespace" means a container keeps the browser from making namespaces: the message ends "Another browser does not help here.", and the user has to let the container allow it, as Docker does with `--security-opt seccomp=unconfined`. "No usable sandbox" or "The SUID sandbox helper binary was found, but is not configured correctly" means that build of the browser lacks the setup its sandbox needs: ask the user to point CHROME_PATH at one whose sandbox is set up, like Google Chrome from its own package, or to make that build's chrome-sandbox owned by root with mode 4755 themselves.
- If it says the browser's profile could not be made in the temp folder, set TMPDIR to a folder this user may write in, with room to spare. If it says the folder the run was started in is gone, set TMPDIR to the full path of one, or run it from a folder that is there.
- If it says the temp folder's path has a `:` in it, or that the stand-ins need a temp folder on a disk that takes links, run it again with TMPDIR set to a folder on the machine's own disk whose path has no `:`, like `/tmp`. No browser was started and no kit written.
- If it says the browser's page crashed while the page was read, the run stops and writes nothing: the machine, or the job the run is part of, had no memory left for the page, as a page that loads very large files can bring about. Tell the user; another try helps only once more memory is free.
- A note that says font files were not read, as the page's came to more than the 200 MB easyfontkit reads of one page, or as one is larger than the 64 MB it reads of one font file, names the first; a family whose file was not read shows with an unknown license that says why, and another run gives the same. A note that names a font the page gave as a `data:` address names it by its media type and size.
- If the browser cannot be told to refuse the downloads a page starts, the run stops, writes nothing and says so, as a site could save files on the machine through it. Point CHROME_PATH at another browser, like a current Google Chrome.
- A note that says the page tried to open an address that is not a web address, such as `mailto:`, and that it was not opened, says what the page did; the kit is read as usual. One that says the page did so in a way easyfontkit stops only on Linux, or may not stop in a browser installed as a snap or a Flatpak, means the system may have opened it with its own program, such as the mail program: tell the user. If the run stops with "<url> led to mailto:..., which is not a web address", the address given sends its visitors there: ask the user for an address of the site's own pages. On macOS, on Windows or with a browser installed as a snap or a Flatpak, the message also says the system may have opened it: tell the user.
